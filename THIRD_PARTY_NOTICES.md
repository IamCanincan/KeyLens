# Third-party notices

The WebUI in `module/webroot/index.html` is a single self-contained file: a
minified, tree-shaken bundle plus inlined fonts and design tokens. It fetches
nothing at runtime.

## What is actually in the shipped artifact

| Shipped content | Source | Version | License |
| --- | --- | --- | --- |
| Component bundle (53 custom elements, tree-shaken to the ones used) | [`@materialwebunofficial/md3e-web`](https://github.com/MD3E-Web-Unofficial/material-web-expressive) | 1.0.14 | Apache-2.0 |
| Design tokens (`tokens.min.css`: colour roles, typescale, shapes, elevation, motion) | same package | 1.0.14 | Apache-2.0 |
| Icon font, inlined as `data:font/woff2` | `Material Symbols Rounded` subset shipped by that package (`dist/fonts/material-symbols-rounded.woff2`, 50 KB, 257 ligatures) | — | Apache-2.0 (Google) |

The package has **no runtime dependencies** (`dependencies: {}`), so nothing else
is linked into the bundle.

`md3e-web` is an independent, unofficial community web adaptation of the Material
Design 3 / Material 3 Expressive specifications; its own `NOTICE` file records
that the design tokens, colour roles, elevation, shape and motion schemes it
implements are specified by Google LLC (Apache-2.0) and that some values are
derived from the AOSP AndroidX Jetpack Compose Material 3 implementation. That
notice applies to this bundle as well.

## What was deliberately left out

* **Roboto** — the package ships five Roboto faces (SIL Open Font License, see
  `dist/fonts/Roboto-OFL.txt`). They are **not** in the artifact: the KernelSU /
  Magisk manager WebView does not apply web fonts here (measured — it falls back
  to the system face regardless), so text is set to `system-ui` and
  `tools/md3e-build/build.mjs` strips every Roboto `@font-face`. Roboto names
  still appear inside `font-family` fallback lists in the library's CSS; they
  resolve to the system font and ship no bytes.
* **Material Symbols Outlined / Sharp** — the library declares three icon
  families but points **all three** `@font-face` rules at the single Rounded
  file above. Inlining all three would ship the same 50 KB three times, so
  `tools/md3e-build/build.mjs` keeps only the `Material Symbols Rounded` face.
  The only library component that puts an Outlined name first is `md-fab`,
  which this WebUI does not import; that premise is guarded at runtime by
  `tools/md3e-build/verify.mjs` (every painted element's first computed
  `font-family` must have a matching face), not by a static scan.

## Icon font: why it cannot simply be dropped

MD3E components render icons as **ligature text** (`expand_more`, `arrow_back`).
If the font does not load, the interface paints those literal words on screen —
that is not graceful degradation. `tools/md3e-build/icon-gate.mjs` therefore
runs before every build and rejects any icon name outside the 257-ligature
subset listed in `tools/md3e-build/vendor/icons.txt`, and
`tools/md3e-build/verify.mjs` keeps one positive and one negative control on the
rendered page (a name in the subset must measure as one glyph; a name outside it
must still measure as the whole word).

## Behaviour taken from other projects

* **参考做法来自 [Tricky-Addon-Update-Target-List](https://github.com/Keyless-Tricky-Addon/Tricky-Addon-Update-Target-List)**
  (Apache-2.0): the *idea* of the app-list row model (whole-row toggle + checkbox +
  selected-first ordering) and of using KernelSU's native `ksu.listPackages` /
  `ksu.getPackagesInfo` / `ksu://icon/<pkg>` bridges instead of shell commands.
  No source code is copied: our implementation is plain DOM + our own command
  layer, and the native bridge calls are documented by KernelSU itself.
  (We briefly shipped a copy of its `more-exclude.json` package list as an
  "unnecessary apps" suggestion; it was removed on 2026-11-04 because keeping
  that list current is a maintenance burden. No of its data remains in this
  repository or in the shipped artifact.)
